# Админская веб-панель

## Общие ожидания

Админка должна быть удобной для ежедневной работы с большим количеством студентов, тестов и ситуационных заданий. Все большие таблицы должны использовать серверную пагинацию.

Интерфейс должен быть на узбекском языке.

## Вход

Админ входит по паролю `ADMIN_PASSWORD`. Текущая модель простая: один пароль для web admin.

## Раздел `Talabalar`

Назначение: поиск студентов, просмотр их результатов, изменение ФИО и выдача повторной сдачи.

Ожидаемое поведение:

- поиск по ФИО;
- поиск по student ID;
- поиск по Telegram ID;
- фильтры по курсу, группе, подгруппе, факультету;
- серверная пагинация;
- выбор размера страницы;
- изменение только ФИО.

Не ожидается:

- изменение курса, группы, подгруппы, факультета через админку.

## Раздел `Test natijalari`

Назначение: проверка и анализ результатов тестов.

Ожидаемое поведение:

- серверная пагинация;
- фильтр по студенту;
- фильтр по группе и подгруппе;
- фильтр по статусу;
- каскадный фильтр `Bo'lim -> Dars -> Test`;
- быстрый просмотр деталей результата;
- выдача повторной сдачи.

Тестов и результатов может быть много, поэтому фронт не должен загружать полный список.

## Раздел `Vaziyatli topshiriqlar`

Назначение: проверка ситуационных заданий.

Ожидаемое поведение:

- серверная пагинация;
- фильтр по студенту;
- фильтр по группе и подгруппе;
- фильтр по статусу проверки;
- каскадный фильтр `Bo'lim -> Dars -> Topshiriq`;
- просмотр ответа;
- ручное оценивание;
- AI-оценивание, если настроено.

## Раздел `Kontent`

Назначение: управление учебным контентом.

Ожидаемое поведение:

- создание, редактирование, удаление разделов;
- создание, редактирование, удаление уроков;
- управление теорией;
- загрузка и замена файлов теории;
- создание и настройка теста;
- ручное создание вопросов;
- импорт вопросов;
- редактирование вариантов ответа;
- создание, редактирование, удаление ситуационных заданий.

Контент должен редактироваться без необходимости постоянно переключаться между разными экранами.

## UX-требования

- Кнопки действий должны быть рядом с объектом, к которому относятся.
- У длинных таблиц должен быть горизонтальный scroll, если данные не помещаются.
- Фильтры должны явно очищаться кнопкой `Tozalash`.
- В таблицах с большим количеством данных нельзя отключать пагинацию.
- ID можно показывать для диагностики, но основной рабочий путь должен быть через названия, поиск и каскадные фильтры.
