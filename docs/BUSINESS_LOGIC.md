# Бизнес-логика

## Роли

### Студент

Студент работает через Telegram-бота. Он может:

- зарегистрироваться;
- менять свои данные, кроме ФИО через админку;
- смотреть уроки;
- получать теоретические материалы;
- проходить тесты;
- сдавать ситуационные задания;
- получать уведомления о проверке.

### Администратор

Администратор работает только через web admin. Telegram-админ больше не используется.

Администратор может:

- управлять контентом;
- смотреть студентов;
- менять только ФИО студента;
- смотреть результаты тестов;
- проверять ситуационные задания;
- выдавать повторную сдачу.

Важно: администратор не должен менять курс, группу, подгруппу и факультет студента. Эти поля студент меняет сам через student bot.

## Учебная структура

Иерархия контента:

1. `Unit` - раздел.
2. `Lesson` - урок внутри раздела.
3. `TheoryMaterial` - теория урока.
4. `Test` - тест урока.
5. `Question` + `AnswerOption` - вопросы и варианты ответа.
6. `SituationalTask` - ситуационное задание урока.

Ожидается, что админ может быстро добавлять, редактировать и удалять контент без знания внутренних ID. ID можно показывать как вспомогательную информацию, но не делать их основным способом работы.

## Тесты

Студент проходит тест через Telegram-бота.

Правила:

- результат сохраняется в `test_results`;
- попытки считаются отдельно;
- статус может быть `in_progress`, `completed`, `timeout`;
- повторная сдача выдается через `test_retakes`;
- после использования повторной сдачи старая блокировка не должна мешать новой попытке.

Админская проверка результатов должна быть серверно-пагинированной. Нельзя загружать тысячи результатов целиком.

Фильтрация должна поддерживать:

- конкретного студента;
- группу;
- подгруппу;
- статус;
- раздел;
- урок;
- конкретный тест.

## Ситуационные задания

Студент отправляет текстовый ответ и, при наличии, фото.

Проверка:

- ручная оценка от 0 до 100;
- AI-проверка, если настроен grading API;
- проходной результат в UI считается от 60 баллов;
- после проверки студент получает уведомление, если student bot token доступен.

Фильтрация в админке должна поддерживать:

- конкретного студента;
- группу;
- подгруппу;
- статус проверки;
- раздел;
- урок;
- конкретное задание.

## Повторная сдача

Повторная сдача может быть выдана для:

- теста;
- ситуационного задания.

Для web admin поле `granted_by` может быть `NULL`, потому что старый admin user id из Telegram-админки больше не обязателен.

## Импорт вопросов

Поддерживается импорт из CSV/XLSX.

Ожидаемый формат:

- вопрос;
- балл;
- вариант A;
- вариант B;
- вариант C;
- вариант D;
- опционально вариант E;
- правильный ответ A-E.

Правильный ответ должен ссылаться на существующий вариант. Если указан `E`, но вариант E пустой, импорт должен быть отклонен до записи вопроса.
